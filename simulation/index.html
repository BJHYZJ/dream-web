From instruction to released placement

Cross-room dynamic pick-and-place

The robot starts without an observed map, scans and explores. Only after a verified visual discovery does the environment move the target. Subsequent observations trigger stale-memory updates and rediscovery. After grasping, the robot searches for the instructed receptacle while retaining its memory.

How to read the videos. Left: external simulator view. Upper right: current head-camera observation. Lower right: observed semantic memory and navigation map; blue is traveled motion and green is the A* route/goal. Captions distinguish external relocation from the robot's later observation-based update. All videos play at 4×; the clock shows original simulation time. No task stages or source frames are removed.

Code and provenance

Run the corresponding task

The simulation directory is independent of the original ROS hardware workflow. After the documented environment and asset setup, the unified entrypoint launches learned perception and closed-loop control from the exact versioned profile corresponding to each case.

python -m simulation.run --preflight
python -m simulation.run --case 01 --output simulation/results/my_case01
python -m simulation.run --all --output simulation/results/my_ten_cases

Installation, task profiles, audit procedure and implementation details · Video manifest and checksums

What these demonstrations show, and what is adapted

These are development-selected executed examples, not a benchmark or an outdoor evaluation. Train/Val/Test in the names identify upstream scene splits; the videos were not selected as a held-out evaluation. Each case has its recorded controller version and seed.

The adapter reuses DREAM's learned semantic voxel memory and A* logic. Simulator odometry replaces the physical SLAM backend, language parsing uses a bounded grammar, and hosted mLLM verification is disabled. Grasp/place poses come from current RGB-D geometry and are executed using feedback-controlled motion templates; this is not AnyGrasp or a learned grasp policy. Robot paths are not prerecorded commands.

Case 05 retains its original score and the documented evaluator correction. Cases 07 and 10 use spectator-only views rendered by independently re-executing the same saved controls; these camera changes are not additional learned-policy trials. Their observation and memory panels remain tied to the original run. The code records these distinctions and retains the separate evaluation evidence.
